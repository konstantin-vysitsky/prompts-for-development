SMOKE-ТЕСТЫ СТРАНИЦ (подробно)

Расположение: `tests/page_smoke/`. Документация: `tests/page_smoke/README.md`. Реестр страниц: `tests/page_smoke/pages.yaml`.

Зачем: быстро проверить, что SSR-страница открывается (не 500), HTML содержит ожидаемое, при необходимости — нет ошибок в консоли браузера и битых CSS/JS.

Два режима:

| Режим | Команда | Скорость | Что ловит |
|-------|---------|----------|-----------|
| Быстрый (default) | без `--browser` | секунды | HTTP 200, нет Internal Server Error, assert_text/assert_selector |
| Браузерный | `--browser` | ~минута на блок | + console.error, pageerror, битые stylesheet/script/document |

CLI:

```powershell
# Точечно — после правки одной страницы
.\venv\Scripts\python.exe -m tests.page_smoke run --pages admin_calls

# Весь admin-блок
.\venv\Scripts\python.exe -m tests.page_smoke run --tag admin

# Авто по git diff (правка шаблона → только связанные страницы)
.\venv\Scripts\python.exe -m tests.page_smoke run --changed
.\venv\Scripts\python.exe -m tests.page_smoke run --changed --include-shared

# Полный прогон через pytest
.\venv\Scripts\python.exe -m pytest tests/page_smoke/test_smoke.py -q

# Проверка доступа (без cookie → /login, user → /)
.\venv\Scripts\python.exe -m tests.page_smoke run --negative
```

Браузерный режим — Chromium (один раз): `.\venv\Scripts\python.exe -m playwright install chromium`

- Сервер уже на 8000: `run --browser --base-url http://127.0.0.1:8000 --pages admin_calls`
- Без `--base-url`: встроенный uvicorn (subprocess, тестовая БД) — медленнее, но автономно

Реестр `pages.yaml` — единый источник правды. Поля записи:

- `id` — ключ для `--pages`
- `path` — URL; `{user_id}` и т.п. через `path_params` → фикстуры из `fixtures.py`
- `auth` — `admin` / `user` / `pro` / `none`
- `tags` — фильтр `--tag`; тег `shared` для layout (`base.html`) при `--include-shared`
- `variants` — query-варианты (`?status=finished`)
- `assert_text`, `assert_selector` — проверки HTML
- `source_files` — для `--changed` (шаблон, роут)
- `skip_browser: true` — WebRTC/LiveKit-страницы (smoke «открылась», без полного звонка)

Если добавили новую SSR-страницу в задаче — обязательно допиши запись в `pages.yaml` с `source_files`, иначе `--changed` её не найдёт.

`--changed`: `git diff --name-only <base>...HEAD` → match с `source_files`. Нет совпадений → exit 0 (не fail).

Аутентификация: cookie `session_token` через `auth_as()` из `tests/api_helpers.py` (TestClient) или cookies в Playwright context.

ИНТЕРАКТИВНЫЙ E2E (опционально, не для каждой задачи)

Когда нужен: критичный UI-флоу из 03_design.md (submit, модалка, фильтр с перерисовкой), smoke+API не ловят регрессию.

Где: tests/e2e/ (отдельные pytest + Playwright) или позже — steps в pages.yaml. Переиспользовать auth, base_url, fixtures из tests/page_smoke/.

Правила:
- Ждать гидратацию React (#*-root, networkidle или expect locator visible)
- Селекторы: data-testid > role+name > текст; не цепляться к CSS-классам темы
- Ошибки/assert — по видимому тексту в DOM (role="alert"), не по toast-only
- LiveKit/звонки — не полный e2e; skip_browser в pages.yaml
- Первый сценарий дороже поддержки; не раздувать без причины

Отладка вручную: `playwright codegen` с --base-url на локальный сервер.
