# Промты для разработки

Набор промтов для ведения задачи по этапам: от описания до анализа и критики.

Промты не привязаны к конкретному проекту. Путь `/задачи/[НАЗВАНИЕ_ЗАДАЧИ]` — это
рабочая папка задачи внутри того репозитория, где ведётся разработка.

## Этапы

Номер этапа совпадает с префиксом файла, который этот этап создаёт.

| # | Файл промта | Роль агента | Результат |
|---|-------------|-------------|-----------|
| 0 | `0-мета-промт.md` | Оркестратор | Запуск всех этапов, порядок работы, правила остановки |
| 1 | `1-описание-задачи.md` | Бизнес-аналитик, UX-проектировщик | `01_task.md` |
| 2 | `2-исследование.md` | Технический аналитик | `02_research.md` |
| 3 | `3-проектирование.md` | Системный архитектор | `03_design.md` |
| 4 | `4-анализ-и-критика-архитектуры.md` | Независимый архитектурный ревьюер | `04_architecture_critique.md` |
| 5 | `5-планирование.md` | Tech Lead | `05_plan.md` |
| 6 | `6-реализация.md` | Разработчик | Код + отметки фаз в `05_plan.md` |
| 7 | `7-тестирование.md` | Инженер по качеству | Отчёт в чат + `06_testing.md` по желанию |
| 8 | `8-анализ-и-критика.md` | Аудитор | `07_issues.md`, `08_audit.md` |

## Соглашения об именах

Файлы внутри папки задачи:

```
01_task.md
02_research.md
03_design.md
04_architecture_critique.md
05_plan.md
06_testing.md
07_issues.md
08_audit.md
```

Исключений нет: этап 4 пишет `04_architecture_critique.md` (критика стоит сразу
после проектирования), этап 8 пишет `07_issues.md` и `08_audit.md`. Дробных
номеров в именах файлов не бывает.

## Как пользоваться

1. Создайте папку задачи: `/задачи/[НАЗВАНИЕ_ЗАДАЧИ]`.
2. Скопируйте текст нужного этапа в чат с агентом.
3. Дождитесь артефакта этапа и проверьте его.
4. Переходите к следующему этапу только по явной команде.

Агент не переходит к следующему этапу сам. Этап 0 описывает мета-правила
для случая, когда этапы запускаются подряд через суб-агентов.

## Важное

- Каждый этап читает артефакты предыдущих этапов — не пропускайте шаги.
- Этап 4 и этап 8 независимы: их задача — найти проблемы, а не подтвердить решение.
- Раздел «Исключения (что НЕ делаем)» обязателен: он фиксирует сознательные отказы.
